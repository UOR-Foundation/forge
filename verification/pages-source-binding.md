# FA-90 — Pages source and observation binding

Authority: `FoundrySpecification.pagesSourceBoundary`, `PagesSourceError`, the FA-90 register row and `features/suites/pages-source-binding.feature`. This is a local repair to the Pages/kernel-pin integration on main `2ec8a0bad86bd8efce7f3d77827ccdb46b22f410`, not a publication coordinator.

## Producer versus adopted source

A fresh build creates `producer.json` before signing. The existing three signing attempts cover both this manifest and the holo; the original manifest stays with the cached page. The new page cache namespace refuses legacy entries without it. Adoption verifies both subjects through GitHub CLI with repository, Pages signer workflow, exact producer source digest and hosted-runner policy. Official flag contract: https://cli.github.com/manual/gh_attestation_verify. There is no handwritten cryptographic verifier or provenance JSON reducer, and unsigned `app.json` is not source evidence.

The input digest covers Git tree mode, object kind, blob identity and path for every tracked file except `studio/`, `v2/`, and other workflows, explicitly retaining the studio producer-claim helper. This conservative superset matches the Pages build's documented input exclusion boundary. Producer and adopted input digests are independently recomputed. A different producer SHA is deliberately allowed for unchanged inputs; altered holo bytes, a false producer/input claim, a different kernel source, or failed signature verification refuse adoption. The workflow checks out the triggering SHA and verifies it is still main before adoption. A later advance remains protected by the existing non-force push, which cannot overwrite the new tip. Manual builds record their actual checkout instead of the workflow event SHA.

## Deployed observation

The existing `pages` concurrency group now covers deployment through live verification and cache save, with no nested same-group lock. Every live step requires the deploy action to have succeeded. A complete assembled-file manifest (including v2), run-specific marker and new cache namespace replace the two-input-address live key. The key additionally binds browser version and harness files. Before reuse and after observation, all artifact files are fetched without cache and hashed, bracketed by marker checks. During a fresh live browser check, every observed manifest-listed static response and worker-owned renderer navigation alias (such as chat and ui routes) is hashed too; failed, unfinished or wrong-byte responses refuse success. Service-worker-generated preview documents are not misrepresented as deployed static files.

This is byte and source identity evidence, not independent proof of GitHub's signing or scheduling services, nor proof that generated preview documents equal static files. Production fetch latency is not qualified. An indicative local HTTP scan of the committed source shell (not the assembled deployment) covered 355 files / 18,187,790 bytes in 820 ms and 450 ms for two 12-concurrent passes. The approach adds two complete artifact transfers on cache hits; deployment lock occupancy increases by live verification duration. It trades that cost for preserving truthful identical-byte live reuse.

## Hosted canonical-generation preparation

The project-owned `canonical-generation.yml` provides the missing writer environment without changing acceptance. It checks out the exact PR head SHA (dispatch SHA otherwise), has only `contents: read`, and passes no token, credentials, Docker socket or host cache into the immutable locked SDK. The command is `cargo fmt --all && just model-write && cd app && lexlean lock && lexlean fmt --all && lexlean lock`; it does not run a duplicate proof build or claim that generated working-tree bytes pass for the original head.

The collector requires HEAD to remain the source revision and reads the SDK and universal-file list from that revision, not the generated tree. Only existing `CONFORMANCE.md`, `app/lexlean.lock`, `app/src/*.lex.tex` descendants and Rust sources under `crates/` or `xtask/` may change. Universal files, unexpected paths, additions/deletions, mode changes and untracked nonignored outputs fail collection. Ignored build intermediates are not patch outputs. The workflow additionally refuses changes to the collector itself before executing it and uploads exactly `canonical.patch` and `receipt.json`. The receipt records source, SDK image, SHA256 of patch bytes and `acceptance: false`. No commit, push, dispatch or automatic patch application occurs.

Four generation controls first failed because the implementation was missing, then passed. They execute Git-backed collection and the workflow's actual writer sequence with controlled command doubles, including failure stopping later writers. Source mismatch, invalid SDK, universal changes, mode changes, deletions, unexpected writes and wrong patch scope are negative controls. Planted source-equality, universal-file and permitted-path bypasses each fail the test suite. Current FA-90 wrapper requires 19 passing tests; together with four existing backlog workflow tests, 23 pass with no skips. The hosted writer itself remains unrun locally because Docker is absent.

Production deployment is now explicitly main-only at job level. The regression evaluates the actual guard for main, feature branch, PR merge and tag refs. A branch Pages dispatch can qualify build and signing without deploying production. After reviewed canonical artifacts are applied and committed, existing bootstrap and all other full exact-head gates must run; this preparation workflow does not excuse stale generated outputs or authorize integration.
