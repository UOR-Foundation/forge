# Application shape and lifecycle authority

FA-84 was registered with its model boundary and scenario before implementation. Three original production-boundary controls failed: a valid stateful editor save raised `invalidCanonicalEdit`, direct lifecycle-file editing was accepted, and an authored `phase: proved` file was trusted without proof authority.

The host now selects one active source shape. Direct stateful saves retain the complete bounded module and still require permission before hosted checking. Explicit decision/stateful conversions atomically retire the former active source and lifecycle. Invalid replacements keep the previous stateful source. Mixed legacy source cannot select or publish an obsolete decision. Generic compilation and portable publication refuse unsupported stateful source rather than substituting scaffold code.

Stateful lifecycle authority lives in the host-owned `stateful:<appId>` reference, captured in the same transaction as source. `prism/app.json` is only a projection. Source and lifecycle predecessor are compared together before writes; ordinary source changes invalidate the protected record. Imports and restored authored files cannot create checked or proved standing. Decision status and stateful standing are removed or installed in the same source transaction during conversion.

Sixteen Node controls exercise the actual editor, conversion functions, source selector, publication handler, protected-state reader and transaction adapter. They cover forged/imported state, source mismatch, mixed authority, lifecycle races, unsupported builds, quoted labels, retained inactive files and live-cache invalidation. A production `saveSpec` plus real editor-history control verifies undo and redo; its planted unconditional-invalidation mutant fails. Same-shape decision edits keep history while shape changes forget old runtime state.

The existing real-IndexedDB browser edit gate now also checks protected-state capture, atomic source/lifecycle replacement, stale approval refusal and invalidation on ordinary source mutation. Its browser run and full exact-SDK acceptance remain required. The Node transaction scheduler is not a browser-storage proof. Approval cancellation has its own gate in `studio/tools/proof_approval_cancellation.test.mjs`, with original-failure and restored evidence in `studio/VERIFICATION.md`.
