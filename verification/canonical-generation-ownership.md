# Canonical generation ownership (FA-37)

Authority: `app/src/FoundrySpecification.lex.tex`,
`canonicalGenerationBoundary` and `CanonicalGenerationError`.

A generic generated-file batch in a project with a decision specification
cannot overwrite, delete or rename its spec, active canonical module or
generated runtime. Both rename endpoints are protected; an unreadable spec
protects top-level canonical modules until repaired. One forbidden operation
refuses the entire batch before mutation. Canonical authoring retains its
separate checked transaction. Caller options cannot replace the core, digest
function or rules lifecycle. Patch and supplied source are copied before await.

Registration and the behavioral scenario preceded implementation. The missing
Node oracle made the Rust acceptance test fail; six initial Node controls failed
on the missing implementation. After implementation, all 224 combined Node
controls pass. Local Rust workspace tests, Clippy, formatting and shell parsing
pass. These checks do not replace the locked SDK's complete `just vv` boundary.

Six restored mutations are rejected by concrete assertion failures: unprotected
writes, unchecked rename targets, unprotected malformed-spec modules, mutable
patch input, caller lifecycle override and lost public error code. The first
mutation script stopped on a whitespace-sensitive replacement assertion; the
corrected script ran all six mutations and restored every source file.

Real Chromium runs the built shell, core, host and IndexedDB. Twelve protected
write/delete/rename attempts leave files, refs and versions unchanged, including
ordinary writes mixed into refused batches. Ordinary generation creates one
version; pre-cancellation leaves storage unchanged. Canonical file editing and
nonmodel generation remain available. The direct canonical editor and generic
batch browser regressions also pass, with no page exceptions. Local provenance
is explicitly diagnostic, not signed release evidence.

This is a generated-file authority boundary, not authentication of same-origin
scripts or proof of whole-application semantic ownership. Exact-head immutable
SDK and Studio CI must pass before readiness.
