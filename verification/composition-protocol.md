# Generated composition protocol evidence

FA-07 implements `CompositionProtocol.boundary` and `adapterBoundary` in
`app/src/CompositionProtocol.lex.tex`. The existing generated byte-dispatch guest
now accepts a bounded composition request, decodes it in LexLean, calls
`FeatureComposition.admitComposition`, and returns the modeled outcome. Existing
phase and permission requests retain their existing 64-byte limit and behavior.

The protocol uses unsigned 32-bit little-endian representation values encoded as lowercase
hexadecimal ASCII and length-prefixed lists. Limits are 32,768 payload characters
(16,384 decoded bytes), 32 features and 64 entries
per list. Truncated, excessive-count and trailing data refuse. The expanded guest
request/allocation bounds are declared in the application model. All semantic
admission remains in the generated guest; the browser module only encodes the
wire representation and decodes known responses from a caller-supplied guest.

## Evidence

Registration, scenario and failing test preceded implementation. Twenty-six guest
acceptance vectors are independently recorded in `composition-wire-vectors.json`
and pinned to the actual application model by the executable codec suite. The
complete SDK `prismpm verify` gate replays those vectors in the compiled guest;
local source checks and mocked dispatch do not substitute for that replay.

Seven Node tests cover byte-for-byte encoding, invalid scalar representations,
exact record fields, list/payload limits, all semantic refusal codes, invalid guest
responses and runtime errors. The adapter tests make no inference that a mocked
guest establishes runtime conformance. Changing endianness caused two failures;
forging acceptance for every response caused two failures. Both mutations were
restored. All 41 local Rust workspace tests passed, including the codec controls,
and every shell module parsed under its browser goal.

Diagnostic LexLean verification accepted seven modules with attestation
`19aec6d2ea9b9d42cda57c1f7997812003ed48816e92f88c35915dda8defa8f5`.
The compiler differs from the lock, so remote locked-SDK verification remains
required. No SDK, template lock, universal gate or vendor implementation changed.

## Completeness review

Author review checked header and field order, scalar endianness, list limits,
truncation/trailing refusal, producer tuples, cumulative admission invocation,
legacy dispatch preservation and acceptance-vector reachability. This is a
self-review, not independent approval. A caller must supply the appropriate
verified guest; this adapter does not fetch or authenticate it. Registry/UI
integration, intent routing and whole-product release acceptance remain separate
specification obligations.

The first SDK attempt rejected the application declaration because the changed
input-allocation bound lacked an exact-boundary vector (PP2009). The bound is
16,400 bytes and the corpus now includes a 16,400-byte request that must return
compositionTooLarge. This field limits guest input allocation, not overall heap
use; it is distinct from the composition contracts' declared resource budgets.

The corpus also covers two-feature dependency admission, missing dependencies,
wrong versions, incompatible producer schemas, both conflict directions, grants,
targets, evidence declarations, duplicate/zero identity and cumulative memory.
Their structured declarations are included beside independently encoded bytes
so the browser codec can be compared without deciding the expected outcome.

## Runtime resource qualification

Revision a6124ef passed complete locked-SDK run 42997750124 and remote build
42997997725. Its exact archive fingerprint was
264f47f41bb2d614ba5a9a29577afc722f00d585aeb10f9cab953784909068f0.
Independent reader replay passed all 73 embedded vectors and all 20 original
wire cases. A separate 16,384-byte payload test then trapped: the generated
non-tail decoder cloned the entire byte buffer per word, exceeding the guest's
fixed 32-page memory ceiling. That successful CI revision is therefore not
sufficient protocol acceptance.

The decoder now uses a tail accumulator, and list parsers carry numeric cursors
instead of repeatedly copying unconsumed word lists. The wire representation
and limits are unchanged. Four added compiled vectors exercise the maximum
payload, 32 features, six dense features with 64-entry lists, and maximum
dependency/input lists. The downloaded-artifact replay tool also retains the
maximum-payload test. The new revision must pass these controls in the locked
SDK and independent runtime before acceptance.

Earlier code-generation failures were resolved by separating uint8 conversion
into its own function and removing colliding exported dispatch/byteAt symbols.
No compiler limits, heap limits, SDK sources or acceptance gates were weakened.

## Text projection closure

The cursor revision reached browser replay, where the dense case failed with
`payloadMatches: false`: raw carriage-return octets in the binary wire were
normalized by the text view. The unmerged wire now uses lowercase hexadecimal
ASCII octets after its header, preserving the same decoded words and admission
semantics. The 32,768-character payload represents the original 16,384-byte
limit. Public request/allocation bounds are 32,776 and 32,784 bytes respectively,
including the header. The allocation-boundary fixture is updated accordingly.
Uppercase and nonhexadecimal input have explicit negative vectors, bringing the
composition corpus to 26. The codec asserts printable canonical representation
for all structured fixtures. Browser acceptance remains mandatory.

The enlarged ASCII stress fixtures exceeded Lean's elaboration depth when each
request was emitted as one large array literal. Their model expressions now
append balanced chunks of at most 4096 bytes. Independent fixture bytes and the
compiled requests are unchanged; the source-binding check pins the complete
assembled expression. No recursion limit or stress case was removed.

Balanced byte arrays resolved elaboration depth but revision 5645b53 still
exceeded the locked application-Lean time limit in build 43004793784 (PP5007).
The printable wire fixtures now use UTF8 encoding of literal ASCII strings,
removing large per-byte array terms entirely. The independently maintained hex
fixtures still pin every byte; no request, expected response, limit or compiler
budget changed.

The UTF8-literal attempt was refused by the locked metadata grammar (PP2001,
run 43006777118). Fixtures now use the supported closed Bytes aliases and append
primitive exclusively: 156 shared definitions, each at most 64 bytes, assembled
in balanced expressions. The independent gate binds every alias body and every
assembled request to the original corpus. No SDK grammar extension or bypass is
introduced.
